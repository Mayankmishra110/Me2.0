# M2-104 — Events log and SSE broadcaster

## What was built
`internal/events` appends rows to the existing `events` table and fans each row out in-process via a
bounded `Hub`. `Bus.Emit` persists then publishes; slow subscribers drop oldest buffered messages and never
block emitters. SPEC §4 SSE kind strings are exported as `Kind*` constants for producers (M2-106 will stream
them). Sortable ids are generated in-package (no new module dep).

## Spec audit
| Requirement (ticket / doc section) | Where in code | Proof |
|---|---|---|
| `events.Emit(ctx, actor, kind, ref, message, data)` writes + publishes | `internal/events/events.go` `Bus.Emit` | `TestEmit_PersistsAndBroadcasts`, `TestEmit_ManySubscribersAllReceive` |
| Slow consumer never blocks emitters | `internal/events/hub.go` `Hub.Publish` (non-blocking send + drop-oldest) | `TestHub_PublishNeverBlocksOnSlowSubscriber`, `TestHub_ActiveSubscriberUnaffectedBySlowOne` |
| Event kinds from SPEC §4 SSE list | `KindJobUpdated`…`KindAlert` in `events.go` | `TestEventKindConstants_MatchSpecSSEList` |

Deviations from ARCHITECTURE / SPEC / DESIGN:
1. **`kind` is a free non-empty string** — ARCHITECTURE §4 treats `events` as the general audit log; SPEC §4
   names five stream kinds exported as `Kind*` constants so SSE producers use exact strings.
2. **No `-race`** on this machine (`CGO_ENABLED=0`); concurrency argued structurally + covered by tests.
