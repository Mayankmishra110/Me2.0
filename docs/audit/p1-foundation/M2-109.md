# M2-109 — Windows build, start at logon, power settings

## What was built
`scripts/build.ps1` builds `web/dist` then a windowless `bin/mayank2.exe` (`-H windowsgui`).
`scripts/install-task.ps1` registers (or replaces) a Windows Scheduled Task "Mayank2" that runs
`bin\mayank2.exe run` at logon with restart-on-failure, and sets AC power settings (never sleep/hibernate,
lid-close does nothing) per ARCHITECTURE §8. Both scripts support `-WhatIf`/dry paths and `-Uninstall`.

## Known gaps and follow-ups
- **Testing incident (disclosed by be-2, verified by ship):** during test development, script-scope PowerShell
  mocks were briefly shadowed by the real `ScheduledTasks` module autoloading, and one debug run registered an
  actual "Mayank2" scheduled task pointing at a fake temp exe. It was removed immediately
  (`Unregister-ScheduledTask`, confirmed gone); AC power settings were never touched because `powercfg` was
  mocked throughout. The test script was fixed to import the real module first, shadow globally, and abort if
  a shadow doesn't take — then it verifies no real task exists before/after each run. Flagging this plainly:
  **be-2 modified real Windows state on Mayank's laptop once, then reverted it.**
- Open question from be-2: should `-Uninstall` also restore the previous power-plan values? Currently it
  leaves AC settings as configured, since the prior values aren't recorded. Needs Mayank's call.
- `powercfg` without elevation was not separately verified beyond the -WhatIf/mocked paths.
