# M2-111 — LLM router and providers

## What was built
`internal/llm.Complete(ctx, task, req)` picks the first available provider for a task from the routing
table in config, falling through on 429/5xx/timeout and tracking each provider's cooldown window in memory
(a DB-backed `quotas` table is a follow-up now that M2-102 has landed). Three provider kinds are implemented:
`ollama`, `openai_compat` (Groq/Cerebras/OpenRouter/Gemini share one HTTP client shape), and `claude_cli`.

Extra guard beyond the ticket text: `TestContentTaskSkipsClaude` proves a content task (research/script/…)
never reaches `claude_cli` even if config mis-routes it — enforces CONTEXT D13/CLAUDE.md ("Claude is for

Deviations: none from SPEC §6. Quota tracking is in-memory rather than the `quotas` table (D2/schema exists
now via M2-102 but wasn't at branch time) — tracked as a follow-up below, not a deviation from the interface.

## Config and keys
Uses the `llm.providers` / `llm.routes` block already in `config/config.example.yaml` (M2-101). Provider API
keys come only from each provider's `key_env` (e.g. `GROQ_API_KEY`); never logged, never in error strings.
`claude` provider needs the `claude` binary on PATH; no key (uses the logged-in CLI session).
