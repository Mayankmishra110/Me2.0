# M2-106 — HTTP API, auth, embedded dashboard

## What was built
`internal/httpapi` is the REST + SSE dashboard API from SPEC §4: token login issuing an
`HttpOnly; SameSite=Strict` session cookie, auth middleware on every route except
`GET /api/health` (and login), bind allowlist for `127.0.0.1` and Tailscale IP only, approvals
list/detail/decision with `approval.decided` events, SSE stream over the M2-104 bus, and an
`embed.FS` SPA stub (`dist/`) with fallback to `index.html`. Missing backing modules return empty
lists. Resume uses bcrypt against `settings.pin_hash` when set.

2. **`golang.org/x/crypto` bcrypt** for resume PIN — already on the phase tree from M2-105; M2-106 uses the same dep (no extra `go.mod` delta after rebase onto 105).
3. **Daemon / `cmd/mayank2` wiring** to call `ListenAndServe` is out of `touches: [internal/httpapi/]`.

## Files
- `server.go` — `Server`, `Options`, `ListenAndServe`, JSON helpers.
- `auth.go` — token hash (SHA-256, constant-time), session store, login rate-limit, cookie + middleware.
- `bind.go` — `ResolveListen` / Tailscale IP lookup (injectable in tests).
- `routes.go` — SPEC §4 mux; pause/resume + PIN; empty stubs.
- `approvals.go` — list/detail/decision + `approval.decided` emit.
- `sse.go` — Subscribe + heartbeat stream.
- `spa.go` — embed + SPA fallback.
- `dist/index.html` — placeholder SPA.
- `*_test.go` / `helper_test.go` — httptest coverage, no real network.

## Config and keys
- `DASHBOARD_TOKEN` (env): required for login; stored/compared as SHA-256 hash on the server; never logged.
- Dashboard listen list from config (`127.0.0.1:PORT`, `tailscale:PORT`); other hosts rejected.
- Optional `settings.pin_hash` (bcrypt) gates resume.
