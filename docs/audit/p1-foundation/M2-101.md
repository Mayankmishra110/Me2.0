# M2-101 — Repo skeleton, config loader, doctor command

## What was built
A `mayank2` CLI (`cmd/mayank2`) with the subcommands `run`, `status`, `doctor`, `migrate`, `set-pin` and `auth`. All of them are stubs except `doctor`. `internal/config` was replaced with the full schema from `config/config.example.yaml`. It resolves relative paths against the config file, loads and validates `config/channels/*.yaml`, loads `.env` without overriding variables that are already set, and gives clear errors on bad values. `doctor` checks the laptop's tools, Ollama (loopback only), disk, RAM, channels and `.env` key presence, and never prints secret values. After the SEC review, Ollama `base_url` is locked to loopback both at config load and in doctor, including on redirects.

## Files
- `cmd/mayank2/main.go`: usage text, subcommand dispatch, stubs, doctor flag parsing (`-config`, `-env`, `-env-example`), default path discovery via `go.mod`.
- `cmd/mayank2/doctor.go`: all doctor checks and the ✅/❌ report; exit 1 if any check fails.
- `cmd/mayank2/sys_windows.go` / `sys_other.go`: disk free (`GetDiskFreeSpaceEx`) and RAM (`GlobalMemoryStatusEx`). On non-Windows both return an error.
- `cmd/mayank2/doctor_test.go`: Ollama loopback and redirect tests using `httptest`.
- `internal/config/config.go`: `Config` schema, `Load`, path resolution, validation, `RequireLoopbackURL`, Ollama helpers.
- `internal/config/channels.go`: channel schema, loading and validation.
- `internal/config/envfile.go`: `.env` loader, `.env.example` key names, presence check.
- `internal/config/config_test.go`: table-driven tests.
- `go.mod` / `go.sum`: `golang.org/x/sys v0.48.0` added.

## Config and keys
- No new config keys. The loader implements the existing `config/config.example.yaml` schema.
- `.env`: read from the repo root. A missing file is not an error. Only key *names* from `.env.example` are checked (24 keys), and values are never printed.
- `llm.providers.<name>.base_url` for `kind: ollama` must be `127.0.0.1`, `::1` or `localhost`, otherwise load fails.
- If `config/config.yaml` is missing, doctor falls back to `config/config.example.yaml`.
- A missing key today makes doctor report ❌ and exit 1. See the D24 deviation above.

## Known gaps and follow-ups
1. **D24 / M2-114:** doctor must show ⚪ for keys that are not configured and must not fail on them (see Deviations).
2. **Empty values count as present.** `EnvKeyPresent` uses `os.LookupEnv`, and all 24 lines in `.env.example` are `KEY=` with no value. After `cp .env.example .env`, doctor reports every key ✅ present even though none is set. Suggest treating an empty value as "not configured" in M2-114.
3. The disk and RAM checks fail on non-Windows (`sys_other.go`). That is fine for this Windows-only product, but CI on Linux would see ❌.
4. There are no unit tests for the doctor report and exit code path, `parseDoctorFlags` or `checkEnvKeys`. Only the Ollama checks are tested in `cmd/mayank2`.
5. `config/formats/*.yaml` loading is deferred to M2-201. The `retry` and `approve` CLI commands are deferred to the queue and approval tickets.
6. `go test -race` was not run because CGO is unavailable on this laptop.
