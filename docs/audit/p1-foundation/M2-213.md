# M2-213 — Storage retention and R2

## What was built
`internal/storage` provides a media folder layout (`raw`/`work`/`renders`/`published`) with path-traversal
guards, a Cloudflare R2 client (aws-sdk-go-v2 S3) for Upload / PresignGET (1h) / Delete, retention
`Cleanup` that deletes local files and optional R2 objects by `delete_after`, and a Windows free-space
check at the 100 GiB low-disk threshold. Alert delivery and scheduler job wiring are out of `touches`.

## Spec audit
| Requirement (ticket / doc section) | Where in code | Proof |
|---|---|---|
| Media folder layout; traversal-safe Path/JobDir | `layout.go` `Layout`/`Path`/`JobDir`/`Ensure` | `TestLayout_Path`, `TestLayout_Ensure`, traversal cases |
| `storage.cleanup` deletes by `delete_after` | `cleanup.go` `Cleanup`/`DeleteAfter` | `TestCleanup_*` (due-only, outside-root refuse, partial failure) |
| Alert when free space < 100 GB (check only) | `diskspace.go` `FreeBytes`/`LowDisk` | `TestFreeBytes_RealPath`, `TestLowDisk` |
| R2 upload + 1h presigned GET via aws-sdk-go-v2 | `r2.go` `Upload`/`PresignGET` | `TestR2Client_UploadAndDelete`, `TestR2Client_PresignGET` (httptest) |
| Object deleted after publish confirmation | `r2.go` `Delete` + `Cleanup` when `R2Key` set | `TestCleanup_DeletesR2ObjectWhenConfigured` |

Deviations from ARCHITECTURE / SPEC / DESIGN:
1. **Low-disk alert delivery** deferred — package exposes `LowDisk`/`FreeBytes` only; Telegram/events
   wiring needs scheduler (out of `touches: [internal/storage/]`).
2. **No real R2 credentials** in CI/laptop — tests use `httptest` fake S3; live R2 unverified.
3. **No `-race`** (`CGO_ENABLED=0` on this Windows host).
