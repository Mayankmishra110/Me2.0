## Goal
A `Publisher` that creates Pinterest pins (Idea/video pins) from an approved render via Pinterest API v5.

## Acceptance criteria
- [x] `internal/publish/pinterest.go` implements `Publisher`: `Platform() string` returns `"pinterest"`; `Publish(ctx, PublishRequest) (PublishResult, error)` is idempotent on `p.IdempotencyKey`.
      Proven: `TestPinterest_PublishHappyPath`, `TestPinterest_Idempotent`.
- [x] Refuses to call the API unless the item's `approvals` row is `status = approved` (D5, F7).
      Proven: `content.RequireApproved` before any Pinterest call; `TestPinterest_MissingApproval`.
- [x] Gets a temporary public URL for the render/thumbnail from `internal/storage` (R2 presigned GET, M2-213) ? Pinterest's pin creation for video takes a `media_source` referencing a hosted URL (or a Pinterest-hosted media upload ID obtained from one), not a raw file upload from this process.
      Proven: cover via `PresignGET` ? `cover_image_url`; video via Pinterest `POST /v5/media` register ? multipart upload to returned `upload_url` ? poll until `succeeded` ? pin with `source_type: video_id`.
- [x] Creates the pin via `POST /v5/pins` on the target board with title, description, the destination link, and the media reference; when the pin is affiliate-linked, the description carries the required affiliate disclosure (COMPLIANCE §1 Pinterest row, FTC row) and the link is a plain outbound URL ? **no link cloakers** (explicit non-negotiable per COMPLIANCE §1).
      Proven: `TestPinterest_AffiliateDisclosure`, `TestPinterest_RejectsCloaker`.
- [x] If Pinterest v5 requires a separate media upload/register step before the pin references it (analogous to Instagram's container step), implement that two-step flow explicitly rather than assuming a single-call pin creation always works for video ? see Notes, this needs verification.
      Proven: verified against official v5 docs ? register ? upload ? poll ? `POST /v5/pins` with `video_id` + mandatory `cover_image_url`.
- [x] Access token loaded from `internal/secrets` (DPAPI vault) by account ref; never logged; refresh-token handling (Pinterest v5 tokens expire and require refresh) surfaces a clear "reauth needed" error rather than a silent retry loop when the API returns an auth error.
      Proven: `TokenSourceFor` injection; `token()` and HTTP 401/403 ? `reauth needed`; `pinRedact` strips tokens from error bodies.
- [x] On success, records `external_id` (pin ID) and pin `url` in `publications`; on failure, wraps errors with `%w`, includes the Pinterest API error detail (not the token) in `last_error`.
      Proven: `completePublication` / `failPublication`; happy-path + HTTP tests.
- [x] Respects the Pinterest cap (? 5 pins/day, COMPLIANCE §4) and the "one pin per destination link per day max" rule (COMPLIANCE §3 Pinterest row) ? fails closed rather than creating a duplicate-destination pin same-day.
      Proven: `TestPinterest_DailyCap`, `TestPinterest_DuplicateDestinationSameDay`.
- [x] Table-driven tests next to the file cover: idempotent replay, missing approval, affiliate-link disclosure present in description when required, duplicate-destination-same-day rejection, and a happy-path pin creation against a fake Pinterest API server (`httptest`).
      Proven: `pinterest_test.go` (also daily-cap + cloaker).

## Notes

### Technical decisions (be-4, 2026-09-28)
- **Video pin flow (verified):** Pinterest API v5 requires four steps for video ? `POST /v5/media` (`media_type: video`) ? multipart POST to returned `upload_url` with `upload_parameters` ? poll `GET /v5/media/{id}` until `succeeded` ? `POST /v5/pins` with `media_source.source_type: "video_id"`, `media_id`, and mandatory `cover_image_url`.
- **Cover URL:** `ThumbnailPath` is an R2 object key (or absolute http(s) URL); `pinPresigner.PresignGET` mints the temporary public cover URL (D20 / M2-213).
- **Board:** `PublishRequest.PlaylistID` carries the destination `board_id`. Per-topic boards remain a config/product choice outside this ticket.
- **Destination link:** first `http(s)` tag; cloaker hosts rejected fail-closed; affiliate disclosure appended when `PaidPromotion` is set.
- **Quotas:** `pinterest:<account>` daily cap 5; `pinterest_dest:<account>:<sha256-prefix>` limit 1 per UTC day.
- **OAuth:** business pin creation needs `pins:write` (+ `boards:read`); refresh failures and 401/403 surface `reauth needed` (permanent in the job handler). Daemon wiring of `TokenSourceFor` ? `internal/secrets` follows the same deferred pattern as M2-211.
- `needs-sec: yes` ? OAuth tokens, publish path, path confinement, R2 cover URLs.
