## Goal
A `Publisher` for the Facebook Page (Reels/video) using the Meta Graph API and a page-scoped access token.

## Acceptance criteria
- [ ] `internal/publish/facebook.go` implements `Publisher`: `Platform() string` returns `"facebook"`; `Publish(ctx, PublishRequest) (PublishResult, error)` is idempotent on `p.IdempotencyKey`, matching the check-before-call pattern used by the other publishers.
- [ ] Refuses to call the Graph API unless the item's `approvals` row is `status = approved` (D5, F7).
- [ ] Gets a temporary public URL for the render from `internal/storage` (R2 presigned GET, M2-213) for the video upload call — same reasoning as Instagram: Meta's video publishing endpoints take a hosted URL (`file_url`), not a multipart upload from this process.
- [ ] Uses a **page-scoped access token**, not the user token — exchanges/loads the page token via `internal/secrets` (DPAPI vault) keyed by the Page ID; document in code comments that page tokens are long-lived but can be invalidated by a password change/permission review, and the publisher surfaces a clear "reauth needed" error (not a silent retry loop) when the Graph API returns an auth error.
- [ ] Publishes as a Reel/video post to the Page feed via the Graph API video endpoint (`POST /{page-id}/videos` or the Reels-specific publish endpoint — see Notes) with title/description from `content_items`; sets the AI-disclosure and paid-partnership fields when the compliance report requires them (COMPLIANCE §1 Meta row).
- [ ] On success, records `external_id` and post `url` in `publications`; on failure, wraps errors with `%w`, includes Graph API `error.code`/`error.message` in `last_error`, never logs the token.
- [ ] Respects the Facebook daily cap (≤ 3/day per account, COMPLIANCE §4); fails closed rather than posting past it.
- [ ] Table-driven tests next to the file cover: idempotent replay, missing approval, page-token auth failure surfaced distinctly from a generic API error, and a happy-path publish against a fake Graph API server (`httptest`).

## Notes
- Not fully certain whether the current recommended path for a Page-owned Reel is the general `/{page-id}/videos` endpoint with `video_state`/container semantics similar to Instagram, or a distinct Reels publishing endpoint — Meta has moved Reels functionality around Graph API versions. **Double-check the current official Meta docs for Facebook Page video/Reels publishing before implementing**; do not assume the Instagram container/publish two-step maps 1:1 onto Facebook.
- Verify current page-token acquisition flow (long-lived Page Access Token via `/me/accounts` after a long-lived User token) is still accurate, since Meta periodically changes token exchange requirements and required permissions (`pages_manage_posts`, `pages_read_engagement`, etc.).
- Same account-linkage note as M2-301: this Page is the parent of the Instagram Business Account, so confirm whether the same stored token can serve both publishers or if they must be fetched/stored separately in `oauth_tokens`.
