## Notes
### Plan (crew-be-2)
- `scripts/build.ps1`: strict mode, stop on error; checks `npm` and `go` are on PATH; `npm ci` in `web/` only when `node_modules` is missing, then `npm run build` → `web/dist`; then `go build -ldflags "-H windowsgui" -o bin/mayank2.exe ./cmd/mayank2` from the repo root. Fixed argument lists, `$LASTEXITCODE` checked after every native call. `-SkipWeb` for Go-only rebuilds.
- `scripts/install-task.ps1`: `[CmdletBinding(SupportsShouldProcess)]`, so `-WhatIf` prints every action without doing it. Task "Mayank2" for the current user: at-logon trigger (this user), action `bin\mayank2.exe run`, working dir = repo root, settings RestartCount 3 / RestartInterval 5 min / ExecutionTimeLimit 0 (no limit) / MultipleInstances IgnoreNew / runs on battery. Power: `powercfg /change standby-timeout-ac 0`, `/change hibernate-timeout-ac 0`, `/setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0`, `/setactive SCHEME_CURRENT`. Prints the 80% battery-limit reminder. `-Uninstall` removes the task only.
- Idempotent: `Register-ScheduledTask -Force` replaces an existing "Mayank2" task; powercfg values are absolute sets.
- Tests: `scripts/tests/install-task.tests.ps1`, a plain PowerShell test script (only Pester 3.4 ships with Windows PowerShell 5.1, so no Pester dependency). It shadows `Register-ScheduledTask`, `Unregister-ScheduledTask`, `Get-ScheduledTask` and `powercfg` with recording functions, runs install / re-install / uninstall / `-WhatIf`, and asserts the recorded calls. Nothing touches the real Task Scheduler or power plan.
- Risks: registering an at-logon task may need an elevated shell on some Windows setups (script reports the error clearly); `-H windowsgui` means `mayank2.exe` prints nothing to a console (use `go run ./cmd/mayank2 doctor` for console output); `run` is still a stub (exits 0), so the task will show "completed" until the daemon lands.

Decisions and caveats:
- Tests are a plain PowerShell script, not Pester: only Pester 3.4 ships with Windows PowerShell 5.1.
- Test pitfall found and fixed: script-scope mock functions lost to the ScheduledTasks module's autoload (triggered by `New-ScheduledTaskAction`), so an early debug run registered a real "Mayank2" task pointing at a temp fake exe. I removed it right away (`Unregister-ScheduledTask`, verified gone); no logon happened in between and power settings were never touched (powercfg was always shadowed). The tests now import the module first, define global shadows, abort if any shadow does not resolve, and compare the real task list before/after.
- As a side effect, that incident showed registering the task works from a non-elevated shell on this laptop.
- `$PSScriptRoot` is empty in param defaults under `powershell -File` on 5.1; the repo root default is resolved in the body (covered by a test).
- `-Uninstall` does not restore power settings (the previous values are unknown). Question for Mayank in the handoff.
- `mayank2 run` is still a stub that exits 0, so until the daemon lands the task will show as completed, not running, after logon. Restart-on-failure only triggers on a non-zero exit.
- Run install from the main checkout: the task points at the folder the script lives in.
