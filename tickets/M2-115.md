## Goal
The dashboard (M2-107) is installable on Mayank's phone/desktop as a Progressive Web App: manifest,
service worker, offline app-shell, home-screen icon — so Telegram approvals aren't the only mobile path.

## Acceptance criteria
- [ ] `web/public/manifest.webmanifest` (name, icons 192/512, `display: standalone`, theme/background from
      DESIGN §1.3 tokens) linked from `index.html`.
- [ ] Service worker (Vite PWA plugin or hand-written) caches the built app shell; a fresh SSE/API call
      still always hits the network — never serves stale job/approval data from cache.
- [ ] Installable: Lighthouse PWA check (or documented manual steps) passes over Tailscale.
- [ ] Works fully offline for navigation between already-visited screens; shows a clear "offline, data may
      be stale" banner rather than silently showing old approvals as current.
- [ ] No change to auth: still requires the same session cookie login over Tailscale (D4) — the PWA shell
      does not weaken or bypass the dashboard's access control.

## Docs
DESIGN §1 · ARCHITECTURE §7 (security — Tailscale-only access must still hold)

## Notes
Added 2026-09-28 at Mayank's request. Service worker must not cache `/api/*` responses for approval or
job data — only static assets — so a stale cache never causes a wrong or delayed approve/reject.
