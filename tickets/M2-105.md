## Goal
Phone control. The bot only talks to Mayank and handles approvals safely.

## Acceptance criteria
- [x] Long-polling `getUpdates` with the offset stored in `settings`; raw HTTPS client, no SDK.
      Proven by `Client.GetUpdates` + `Bot.Run` writing `settings.telegram:offset`; `TestOffsetStored`.
- [x] Drops (and logs as an event) any update whose `from.id` or `chat.id` is not configured.
      Proven by `TestStrangerIgnored`, `TestStrangerWrongChat` (events kind `telegram.ignored`).
- [x] Commands: `/status`, `/today`, `/queue`, `/pause`, `/resume` (PIN prompt, bcrypt check), `/topic`, `/blog`, `/help`.
      Proven by `commands.go` + `TestHelpAllowlisted`, `TestPINRequiredForPause`, `TestPINRequiredForResume`, `TestNoShellFromCommands`.
- [x] `approval.request` job sends a preview (video/photo/text) with buttons; callback `approve|reject|redo:<id>:<nonce>`; nonce single-use; message edited to show the decision; redo asks for a note.
      Proven by `TestApprovalRequestSendsButtons`, `TestDoubleTapIgnored`, `TestRedoAsksForNote`.
- [x] No command executes a shell or arbitrary code.
      Proven by design (no `os/exec`); `TestNoShellFromCommands` stores evil text as topic data only.
- [x] Tests with an `httptest` fake Bot API: stranger ignored, double tap ignored, PIN required.
      Proven by `bot_test.go` (`fakeAPI` httptest server).

## Notes

**Plan (2026-09-28, crew-be):**
1. `internal/telegram`: raw HTTPS Bot API client (no SDK); long-poll `getUpdates` with offset in `settings` key `telegram:offset`.
2. Allowlist: require `from.id` **and** `chat.id` match env `TELEGRAM_USER_ID` / `TELEGRAM_CHAT_ID`; strangers → drop + insert `events` row (`telegram.ignored`); never log token/PIN.
3. Commands (text only, no shell/exec): `/status`, `/today`, `/queue`, `/pause`, `/resume` (PIN prompt → bcrypt vs `settings.pin_hash`), `/topic`, `/blog`, `/help`. Pause/resume via `queue.Pause*` / `Resume*` (`all`|`heavy`|`light`|`net`).
4. `approval.request` handler: send video/photo/text + Approve/Reject/Redo buttons; callback `approve|reject|redo:<id>:<nonce>`; single-use nonce (clear on decide); edit message; redo → ask note then store.
5. Emit events by writing `events` table directly (M2-104 not yet on this base); inject `*queue.Queue` for pause; `golang.org/x/crypto/bcrypt` for PIN (touches go.mod/sum).
6. Tests (`httptest` fake Bot API, no network): stranger ignored+event; double-tap ignored; PIN required for resume; happy-path allowlisted command + approve once.
7. **needs-sec: yes** — telegram allowlist, callback nonces, PIN/bcrypt.

QA: changes — 2026-09-28 — Scope OK (`internal/telegram/` + justified `golang.org/x/crypto` + ticket). SPEC §7 green on go1.27.0; httptest ACs covered. Blockers: (1) ARCH §7 PIN for bulk `/pause`, (2) bot token can appear in logged HTTP errors, (3) preview paths not confined to `data/`.

1. `internal/telegram/commands.go:125-134` — `/pause` for `all|heavy|light|net` applies immediately. ARCHITECTURE §7: "`/resume` and bulk actions need a PIN". Gate bulk pause like `/resume` (prompt → bcrypt → then pause); test that wrong/missing PIN leaves the queue running.
2. `internal/telegram/client.go:56-58` + `bot.go:148` — `methodURL` embeds `TELEGRAM_BOT_TOKEN` in the path; `http.Client` transport errors include that URL (`URL.Redacted()` does not redact path tokens), and `getUpdates failed` logs `error`. Wrap/redact so logs/errors never contain the token.
3. `internal/telegram/approval.go:61-64` + `client.go:155-159` — `SendPhoto`/`SendVideo` open `preview_path` with no `data/` confinement. Reject (or fall back to text-only) paths outside the media/data root before upload.

SEC: changes — 2026-09-28 — Allowlist-before-handler, single-use nonce, resume PIN/bcrypt, fixed HTTPS default, no `os/exec`, D24 empty-token disable look good; same three fixes required before ship.

1. `internal/telegram/client.go:56-58` / `bot.go:148` — token-in-URL must not appear in returned or logged errors (unit-test a forced transport error string has no token).
2. `internal/telegram/commands.go:125-134` — PIN-gate bulk `/pause` per ARCH §7 (resume + destructive/bulk).
3. `internal/telegram/approval.go:61-64` — confine preview reads under `data/` (or configured media root); do not upload arbitrary filesystem paths to Telegram.
