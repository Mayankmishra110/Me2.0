## Goal
A durable queue on the `jobs` table with leases, retries, dead-letter and resource-class worker pools.

## Acceptance criteria
- [x] API from SPEC §3 (`Register`, `Enqueue` with `RunAt/Priority/Parent/ContentID`, `Permanent(err)`).
      `go doc ./internal/queue` in Notes below matches SPEC §3 exactly.
- [x] Atomic claim (UPDATE … RETURNING), lease 5 min, heartbeat every 60 s for running jobs, expired leases requeued at startup.
      `claim` in `worker.go` (UPDATE…WHERE id=(SELECT…LIMIT 1) RETURNING …); `WorkerPoolConfig` defaults
      `LeaseTTL=5m`, `HeartbeatInterval=60s`; `RecoverExpiredLeases` requeues expired `running` rows, meant
      to be called at startup before `StartWorkers`. Proven by `TestClaim_concurrentNeverDoubleRuns`,
      `TestCrashRecovery_expiredLeaseIsReclaimedAndRun`.
- [x] Backoff 1m/5m/30m/2h; after `max_attempts` → `dead` and an `alert` event.
      `backoffSchedule`/`backoffFor` in `worker.go`; `finalizeError` dead-letters + inserts an
      `events(kind='alert')` row on `max_attempts` exhaustion. Proven by `TestBackoffFor_schedule`,
      `TestFinalizeError_retriesWithBackoffThenDeadLetters`.
- [x] Pools: heavy=1, light=4, net=2 (from config); workers skip claiming while paused (global or per agent).
      `WorkerPoolConfig{HeavyWorkers,LightWorkers,NetWorkers}` sized by the caller from
      `config.QueueConfig` (already in `config/config.example.yaml` from M2-101); `pause.go` implements
      global (`pause:all`) and per-resource-class (`pause:resource:<class>`) pause — see Notes for why
      "per agent" is scoped to resource class in this ticket. Proven by `TestPause_globalAndPerResource`,
      `TestStartWorkers_skipsClaimingWhilePaused`.
- [x] Tests: concurrent claim never double-runs a job; crash recovery; retry timing; pause.
      See the full `go test ./internal/queue/... -v` output in Notes below (17 tests, all pass;
      `TestClaim_concurrentNeverDoubleRuns` also re-run `-count=20` clean).

### Plan (2026-09-28)

Files (all under `internal/queue/`):
- `queue.go` — `Resource`, `Handler`, `Job`, `Queue`, `New(db *sql.DB, opts...)`, `Register`, `Enqueue`
  (+`EnqueueOpt`: `RunAt`/`Priority`/`Parent`/`ContentID`), `Permanent(err)`/`IsPermanent`.
- `id.go` — small in-package ULID generator (Crockford base32, ms timestamp + crypto/rand payload).
  No new go.mod dependency; `google/uuid` is indirect-only and not a ULID.
- `worker.go` — `WorkerPoolConfig{HeavyWorkers,LightWorkers,NetWorkers,PollInterval,LeaseTTL,HeartbeatInterval}`,
  `StartWorkers(ctx, cfg) *sync.WaitGroup`, atomic claim (`UPDATE … WHERE id = (SELECT … LIMIT 1) RETURNING *`),
  heartbeat ticker per running job, panic-recovering handler invocation, backoff schedule
  1m/5m/30m/2h keyed off `attempts`.
- `recover.go` — `RecoverExpiredLeases(ctx) (int, error)`: requeues `running` jobs whose `lease_until` has
  passed; called at startup by the caller and safe to call periodically as a background safety net.
- `pause.go` — reads/writes `settings` (`pause:all`, `pause:resource:<heavy|light|net>`); workers skip
  claiming while paused.

Design decisions (docs don't fully specify, deciding and recording per `_engineer.md`):
1. **`failed` vs `dead`**: `queue.Permanent(err)` → status `failed` (terminal, no retry, no alert — an
   expected/handled non-retryable failure). Exhausting `max_attempts` on an ordinary error → status `dead`
   + an `events` row with `kind='alert'` (matches the ticket's "after max_attempts → dead and an alert
   event"). Both are terminal and re-queueable via `POST /api/jobs/{id}/retry` (future ticket).
2. **"per agent" pause**: this ticket only owns resource-class pools, so "per agent" is implemented as
   per-resource-class pause (`pause:resource:heavy|light|net`) plus a global `pause:all`. Per-job-type or
   per-channel pause, if wanted later, layers on top in httpapi/telegram tickets.
3. Concurrency safety for "claim never double-runs a job" relies on `internal/db.Open` already setting
   `SetMaxOpenConns(1)` (single physical connection), so `database/sql` serializes the claim statement across
   goroutines; the atomic `UPDATE … RETURNING` makes each claim also correct against process-external writers.
4. Handler panics are recovered and converted into a retryable error (daemon must survive a bad handler).
5. Attempts are only incremented on an actual handler run (success/fail). Lease-expiry recovery (crash
   recovery) resets a job to `queued` without incrementing `attempts` — the handler never got to run to
   completion, so it isn't "an attempt" against `max_attempts` in the sense of handler logic failing; it's
   still bounded because each *executed* attempt increments the counter once it actually runs.

Tests (table-driven, `internal/queue/*_test.go`, injectable clock, no real sleeps for timing logic, only
short bounded waits for goroutine synchronization):
- Register/Enqueue: bad payload (unmarshalable), unregistered job type, defaults (`RunAt`=now, `Priority`=0),
  opts applied.
- Claim: concurrent claim across goroutines never double-runs a job (race-detector run).
- Backoff timing: 1m/5m/30m/2h per attempt count, exact `run_at` assertions via fake clock.
- Max-attempts exhaustion → `dead` + one `events` alert row.
- `queue.Permanent(err)` → `failed`, not retried, `events` untouched.
- Handler panic → recovered, treated as retryable error.
- Crash recovery: manually claim a job (simulating a worker that died before finishing), advance the fake
  clock past `lease_until`, call `RecoverExpiredLeases`, assert it's back to `queued` with lease/worker
  cleared, then let a real worker pick it up and run it.
- Pause: global and per-resource pause stops claiming for that class only; resume un-blocks it.

If anything here turns out to contradict ARCHITECTURE/SPEC once QA reads it, flag under Review rather than
silently reinterpreting again.

**Bug found and fixed while testing, worth flagging to other `be` tickets that will scan JSON columns:**
scanning a SQLite `TEXT` column directly into a `json.RawMessage`-typed destination fails on this Go
toolchain (`sql: Scan error … unsupported Scan, storing driver.Value type string into type *jsontext.Value`)
— `database/sql`'s reflect fallback only special-cases the exact type `*[]byte`, not a named `[]byte` type
like `json.RawMessage`, and `modernc.org/sqlite` returns `string` for `TEXT` columns rather than `[]byte`.
Worked around in `scanJob` (`worker.go`) by scanning into a plain `string` and converting to
`json.RawMessage` afterward. Any other package (`httpapi`, `content`, etc.) scanning `payload`/`result`/
`script`/`compliance`/`signals`/`data` JSON `TEXT` columns will hit the same thing.
