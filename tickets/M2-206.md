## Notes

### Plan (before coding)
1. uv project at `media-tools/` with console script `mediatools` → `mediatools.cli:main`.
2. Shared JSON IO (`--in` / `--out`): validate required keys; write result JSON; stderr + non-zero on failure.
3. `tts`: Kokoro `KPipeline` — `lang` en→`a`, hi→`h`; voice from input; write wav (24 kHz) + `words[]` from `result.tokens` (proportional fallback when tokens missing, e.g. HI).
4. `stt`: faster-whisper CPU `int8`, `model_size` from input; return `segments[]` + nested `words[]`.
5. Offline after download: refuse network when models missing if `MEDIATOOLS_OFFLINE=1` / hub offline env; document preload.
6. Tests: fixture WAV + mocked engines for contract; live tests marked skip without models. ruff + pytest.
7. README: setup (uv, espeak-ng), JSON schemas, smoke commands. Flag `needs-sec: yes` (child-process / model download surface).
8. Risks: Kokoro HI token timings weak; 16 GB heavy class; torch/CPU install size.

needs-sec: yes — downloads models via HF hub on first run; Go will later exec with fixed argv (no shell from AI text).

### How proved

- STT live: tiny/int8 on EN wav → text `Hello.`, one segment + word timings (exit 0, ~23s first download).
- Offline contract: unit tests with mocked pipeline/model; failure paths return exit 1 + `error:` on stderr.
- `MEDIATOOLS_OFFLINE=1` sets `HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE` before model load.
