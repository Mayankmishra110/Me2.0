## Notes
### Plan (crew-be-3, 2026-09-28)
- Files: `internal/media/stock.go` (types, `Stock` fetcher, download), `stock_pexels.go`, `stock_pixabay.go`,
  `stock_usage.go` (`UsageStore` + in-memory impl), tests next to them with `httptest` TLS servers and JSON fixtures in `internal/media/testdata/`.
- D24: `NewStockFromEnv` enables Pexels only if `PEXELS_API_KEY` is non-empty, Pixabay only if `PIXABAY_API_KEY` is non-empty.
  Neither key → typed `*NotConfiguredError` (`errors.Is(err, ErrStockNotConfigured)`), no panic.
- `Stock.Fetch(ctx, FetchRequest{ChannelID, JobDir, Keywords, Orientation, Count, MinSeconds})` searches providers in order,
  filters by orientation, skips clips used on that channel within 30 days (`UsageStore`), downloads over https only into `JobDir`,
  bounded by `MaxBytes` and a per-download timeout, records sha256/bytes, writes a `.license.json` sidecar, then records the use.
- Every `StockAsset` carries provider, provider asset id, source page URL, license URL, download path. Candidates lacking a page URL are dropped.
- Risks: Pixabay puts the key in the query string, so transport errors are stripped of the URL before wrapping (never log keys).
  DB-backed `UsageStore` waits for M2-102 (follow-up). `assets` table (ARCHITECTURE §4) has `license_url` but no source page/provider columns (question below).

### Implementation (crew-be-3)
- `internal/media/stock.go`: `Stock`, `NewStock`, `NewStockFromEnv`, `FetchRequest`, `StockAsset`, `LicenseRecord`,
  `NotConfiguredError` / `ErrStockNotConfigured`, `ErrNoStockMatch`. `stock_pexels.go` (Pexels `GET /videos/search`, key in
  `Authorization` header), `stock_pixabay.go` (Pixabay `GET /api/videos/`, key in query as that API requires; `safesearch=true`,
  `video_type=film`; the video API has no orientation param so orientation is filtered on rendition width/height).
  `stock_usage.go`: `UsageStore` + `MemoryUsageStore`. Fixtures: `internal/media/testdata/*.json`.
- D24: a provider is on only when its key is set and non-blank (a copied `.env.example` sets empty values, which count as missing).
  No keys → `*NotConfiguredError{MissingEnv: [...]}` (names only), `errors.Is(err, ErrStockNotConfigured)`. No panics.
- Selection: providers in order (Pexels, then Pixabay); a failing provider is logged (provider + status, no URL/key) and the next is tried.
  Rendition = widest mp4 whose long edge is ≤ 1920 (`MaxWidth`). Fewer clips than `Count` is not an error; zero is `ErrNoStockMatch`.
- Downloads: https only (redirects to non-https refused), `MaxBytes` 200 MiB (Content-Length, declared Pixabay size, and a
  `LimitReader` on the stream), 5 min per-download timeout, written to a `.part` temp file then renamed; nothing is left on failure.
  Each clip gets `stock-<provider>-<id>.mp4` + `stock-<provider>-<id>.license.json` sidecar (full license record, sha256, bytes).
- Reuse: `(channel, provider, asset id)` last-use time; used if `now - last < 30d`. Use is recorded only after a successful download,
  so a failed download does not burn the clip. Check+download+record is serialised per `Stock` by a mutex (in-process only; the
  SQLite store should make this atomic across processes).
- Keys: `*url.Error` is unwrapped so the request URL (Pixabay key) never lands in errors/logs — `TestFetchPixabayKeyNeverLeaks`.
- No new config keys (defaults live in code; env names already in `.env.example`).
- Hook note: `phase/p1-foundation` lacks main's `254176d` (M2-111 BOM fix), which makes `go test ./...` fail in `internal/tickets`
  and blocks every Go commit. I cherry-picked it unchanged (`git cherry-pick -x`, b6a19bd); it is identical to main's commit.
