### Plan (crew-be, 2026-09-28)
1. `internal/media/render.go`: child-process wrappers (ARCHITECTURE §2) for media-tools TTS,
   Remotion CLI render/still, ffmpeg mux + `loudnorm=I=-14`, pure-Go `.srt` from word timings,
   file digest (sha256/bytes). Inject `ExecRunner` for tests (no real ffmpeg/uv/node required).
2. `internal/content/render.go`: queue handlers `voice.tts`, `render.long`, `render.short`,
   `render.thumbnail` all `ResourceHeavy`; stage assets under remotion `public/jobs/<id>/`;
   write finals under `storage` renders; INSERT `assets` with sha256/bytes/delete_after
   (`storage.DeleteAfter(now, retentionDays)` provisional until publish).
3. Payloads self-contained (no `script.go` / formats/). Composition IDs map format+orientation
   to Remotion hyphen IDs (M2-208). Idempotent: existing asset rows + files → skip re-render.
4. Tests: WriteSRT / CompositionID / loudnorm+mux argv; handlers with fake runner + SQLite.
5. Risks: Remotion needs files under `public/`; ffmpeg absent on this laptop → mocked in unit tests.
6. `needs-sec: yes` — child-process exec (fixed argv, no shell from AI text).

### How proved
- Heavy class: `RegisterHandlers` → `queue.Register(..., ResourceHeavy, …)` for all four types;
  DB `jobs.resource` asserted in `TestRegisterHandlers_heavy`.
- TTS → `renders/<content_id>/voice.wav` + asset row; idempotent skip on re-run.
- Long: Remotion landscape → mux → loudnorm −14 → `long.mp4` + `subs.srt` (+ thumb when text/clip present).
- Short: Remotion portrait → same pipeline → `short.mp4` + subs.
- Thumbnail: Remotion `still` composition `thumbnail` → `thumb.png`.
- No live ffmpeg/Remotion/Kokoro in CI; `ExecRunner` fakes write outputs. Live smoke is a follow-up
  once ffmpeg is on PATH.
