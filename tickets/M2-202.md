## Notes

### Plan
1. `internal/content/scout.go` — Scout stage: gather candidates from YouTube Data API
   (search.list + videos.list, quota-budgeted), configured RSS feeds, and optional Trends
   (enabled only when TrendsBaseURL is set — D24 skip-clean). Niche keywords from
   CONTENT_STRATEGY §2 pillars keyed by channel.Niche.
2. Score each candidate: `demand × freshness × fit × (1 − competition)`, clamp factors
   to [0,1]. After week 4 (warmup ≥ 28d), blend with `scores` table topic analytics
   (`0.7*base + 0.3*analytics`). Keep ~20% of written slots as exploration picks from
   below the top cut. Manual topics get `ManualBoost` (default 1.5×) and source=manual.
3. Dedup by normalized title against recent `topics` for the channel; INSERT survivors
   into `topics` with signals JSON.
4. Tests: httptest + committed fixtures (no real network); table-driven scoring/dedup/
   exploration/manual-boost/quota-stop; in-memory SQLite via internal/db.
5. Risks: YT quota burn — hard daily unit budget per Scout run. Trends has no public
   Google API — optional injectable endpoint only. Config/scheduler wiring deferred
   (touches = scout.go only); callers pass Options / env key `YOUTUBE_API_KEY`.
