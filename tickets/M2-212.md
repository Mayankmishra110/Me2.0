### Independent qa+sec audit (2026-09-28, post-merge)
QA: pass — confirmed token handling matches the M2-211 pattern (no logging, injectable
`TokenSourceFor`). One coordination finding worth recording here (not exploitable today, since nothing
is wired into `cmd/mayank2` yet, but a real landmine for whoever writes the wiring ticket):
`internal/analytics/pull.go:22` defines `JobAnalyticsPull = "analytics.pull"` and registers the real
handler via `(*Service).RegisterHandlers` (`pull.go:437`, `q.Register(JobAnalyticsPull, ...,
s.Handle)`). `internal/scheduler/handlers.go:21` independently registers a **placeholder** no-op
handler for the identical string, `q.Register(JobAnalyticsPull, ..., placeholderHandler(JobAnalyticsPull))`.
`queue.Queue.Register` (`internal/queue/queue.go:127-143`) silently overwrites
`q.types[jobType]` on a duplicate call — no error, no log — so whichever `RegisterHandlers` call runs
last on the shared queue wins, silently. If the wiring ticket calls the scheduler's `RegisterHandlers()`
after `analytics.Service`'s (or vice versa, without removing the placeholder), analytics pulls will
either silently run as a no-op or the placeholder will silently vanish with no signal either way.
Recommend the wiring ticket delete the scheduler's `analytics.pull` placeholder in the same change that
wires the real handler, and consider making `queue.Register` panic (or the caller check) on a duplicate
job-type registration so this class of mistake can't ship silently.
SEC: pass — confirmed independently; no new secret-handling findings.
