## Goal
Mayank puts one free key (e.g. `GEMINI_API_KEY`) in `.env` and everything that key enables works. Everything
without a key is switched off cleanly, and `doctor` shows it as "not configured" instead of failing.

## Acceptance criteria
- [x] Each integration (every LLM provider, Pexels/Pixabay, each publishing platform, R2, Telegram) counts as
      **enabled** only when its `.env` keys are present, or when config says `enabled: true`. A disabled
      integration never crashes the daemon, and the router skips providers that aren't configured.
- [x] `doctor` prints ✅ ok · ⚪ not configured (feature off) · ❌ broken. It exits non-zero only on ❌
      (a core tool missing, a key set but rejected, or an enabled feature missing a key).
- [x] `mayank2 llm ask [--task script] "<prompt>"` goes through `internal/llm`, then prints the provider,
      model and answer. With only `GEMINI_API_KEY` set and `llm.providers.gemini.model` filled, it works live.
      (Code path proven with `httptest` — see Verification. No real `GEMINI_API_KEY` exists in this
      sandbox, so the *live* Gemini call was not exercised; see Notes.)
- [x] `config.example.yaml` has a current free Gemini model (checked against Google's docs on the day of the
      change, date noted in a comment). README gets a "Quick start with one free key" section.
- [x] Table-driven tests: no keys → all ⚪ and exit 0; Gemini only → gemini enabled, the others skipped; a key
      set but rejected (httptest 401) → ❌.
- [x] Telegram missing → ⚪ with the note "approvals only on dashboard". (Default; Mayank may change it.)
