## Notes

### Plan (be, 2026-09-28)

Files (all under `internal/scheduler/` only):
- `scheduler.go` — `Scheduler` wrapping `robfig/cron/v3` with `cron.WithLocation(cfg.Location)`;
  `New`, `RegisterHandlers`, `Start` (catch-up then cron), `Stop`. Cron callbacks only call
  `queue.Enqueue` (never run handlers inline).
- `schedule.go` — daily HH:MM → cron spec + `previousFire(now)` for catch-up/dedup.
- `catchup.go` — on startup, for each job: if last fire watermark (settings
  `scheduler:last:<type>`) is before the most recent scheduled slot, enqueue once and advance
  watermark. First boot: watermark only (no historical spam). Cron path dedups via same watermark.
- `summary.go` — `summary.daily` handler builds DESIGN §2 text from DB (published per channel,
  pending approvals, failures, best performer last 24h, free-tier quota left, disk free, Claude
  limit state) and sends via injectable `Messenger` (Telegram wired later from `cmd`).
- `cleanup.go` — `storage.cleanup` handler: load due `assets` rows, `storage.Cleanup`, optional
  R2 via `NewR2FromEnv` (D24 nil if unset), low-disk check via `storage.LowDisk`.
- `placeholders.go` — register no-op handlers for `scout.topics` and `analytics.pull` so enqueue
  works until those tickets own real handlers.

Schedules (configured TZ): `summary.daily` = `telegram.daily_summary_at`; `storage.cleanup` =
03:00; placeholders `scout.topics` 06:00, `analytics.pull` 07:00 (constants until channel calendars).

Tests: schedule/previousFire table; catch-up enqueues missed once + first-boot watermark; cron
path only enqueues (fake queue); summary text sections from fixture rows; cleanup loads due rows.

Risks: `cmd/mayank2 run` wiring is out of `touches` — package is ready to wire. needs-sec: no
(no secrets/auth surfaces; R2 env read is storage's existing D24 path).
