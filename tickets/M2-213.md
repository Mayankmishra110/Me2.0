## Goal
The disk stays healthy; Meta publishers get temporary public URLs.

## Acceptance criteria
- [ ] Media folder layout (raw/work/renders/published); `storage.cleanup` deletes by `delete_after`; alert when free space < 100 GB.
- [ ] R2 upload + presigned GET URL (1 h) via aws-sdk-go-v2 S3; object deleted after publish confirmation.

## Docs
CONTEXT D20 · ARCHITECTURE §8

## Notes

### Plan (be-4, 2026-09-28)

Files (all new, under `internal/storage/`):
- `layout.go` — `Layout` over `config.DataDir`: resolves `data/media/{raw,work,renders,published}`,
  `Path(kind, parts...)` joins + validates the result stays under `<root>/<kind>` (path-traversal
  guard: clean-join then prefix-check against the kind root; rejects `..` escapes). `Ensure()`
  mkdirs all four. `JobDir(id)` = `work/<id>` per ARCHITECTURE §2 child-process contract.
- `r2.go` — S3-compatible client over `github.com/aws/aws-sdk-go-v2/service/s3` (already in the
  README stack table; not yet in go.mod — adding it). `NewR2FromEnv` reads
  `R2_ACCOUNT_ID`/`R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`/`R2_BUCKET`; all four required
  non-blank (D24) or it returns `*NotConfiguredError` (never panics), mirroring
  `internal/media.NewStockFromEnv`'s pattern. Endpoint is overridable so tests point at an
  `httptest` fake instead of real R2. `Upload` (PutObject) and `PresignGET` (1h default, caller can
  override) round out the ticket's R2 half. `Delete` (DeleteObject) is used by cleanup after
  publish confirmation.
- `cleanup.go` — `CleanupItem{Path, R2Key, DeleteAfter}` (mirrors the `assets` table's
  `path`/`r2_key`/`delete_after` columns from M2-102; this package stays DB-free, the caller —
  scheduler's `storage.cleanup` job, a later ticket — loads rows and passes them in).
  `DeleteAfter(publishedAt, retentionDays)` computes the cutoff from
  `config.Content.RetentionDays`. `Cleanup(ctx, root, items, r2, now)` deletes local files at/after
  their `DeleteAfter` (path re-validated against `root` before unlink — never deletes outside it),
  and the matching R2 object when `r2` is configured and `R2Key` is set; R2 not configured just
  skips the R2 side, it's not a cleanup failure. Partial failures collect per-item, one bad item
  doesn't abort the run.
- `diskspace.go` — `FreeBytes(path)` via `golang.org/x/sys/windows.GetDiskFreeSpaceEx` (already a
  dependency; Windows-only per CONTEXT §3 hardware). `LowDiskThresholdBytes = 100 << 30`. Returns
  free bytes + a bool; wiring the actual Telegram/events alert is the scheduler's job (out of this
  ticket's `touches`), so this ticket exposes the check, not the alert delivery.

Config: `content.retention_days` already exists (M2-101). No new config keys needed. R2 env keys
already in `.env.example` (M2-101/scaffolding). Adding `github.com/aws/aws-sdk-go-v2/service/s3`
(+ its `credentials`/`config` transitive packages) to `go.mod` via `go get`.

Tests (table-driven, `_test.go` next to each file):
- `layout_test.go`: valid paths per kind; traversal rejected (`..`, absolute-looking segments,
  deep `../../..`); `Ensure` creates all four dirs.
- `cleanup_test.go`: only items at/past `DeleteAfter` are deleted; items outside `root` are
  refused (not deleted) and reported as an error, not silently skipped; R2 delete called only when
  `R2Key` set and client configured; R2-unconfigured path still deletes local files.
- `r2_test.go`: `httptest` fake S3 endpoint (no real network/keys) — Upload + PresignGET
  round-trip, presigned URL host/query shape and ~1h expiry; `NewR2FromEnv` with zero keys →
  `NotConfiguredError`; with a partial set (1-3 of 4) → `NotConfiguredError` naming exactly the
  missing ones; never panics either way.
- `diskspace_test.go`: `FreeBytes` returns a plausible (>0) value for a real path; `LowDiskThresholdBytes`
  comparison table.

Risk: aws-sdk-go-v2 pulls in several transitive modules (smithy-go, credentials, internal/v4)
that aren't in go.mod yet — first `go get` needs network (confirmed reachable to
proxy.golang.org). No compliance/approval-path touch; this package has no publish or public-write
side effect on its own.
