## Goal
`builder.implement` job that, for one approved subphase, creates or reuses a git worktree in the target repo, runs `claude -p` headless (Opus 5.5, `config.builder.implementer_model`, per D7) with that subphase's plan file and ticket(s) as context, commits the resulting work on a build branch, and emits `subphase.done` so the Auditor (M2-503) can start on it while this job moves to the next subphase (D7's core parallelism). This job must never push to, check out, or otherwise modify the target repo's `main` branch (CLAUDE.md non-negotiable, ARCHITECTURE §7).

- Usage limits: stderr/stdout text matching `usage limit` / `rate` / `429`.

### Enforcement split
- Claude Code permission layer: `--disallowed-tools` (defense in depth).
- This job: `rejectForbiddenGitArgs` on every git argv before exec; refuse commit if HEAD is main; assert `refs/heads/main` unchanged after run; on drift `restoreMainRef` (fixed `update-ref`, bypasses the deny gate) then Permanent-fail.
- `requireApprovedPlan`: always `kind=plan`; when both `approval_id` and `content_id` are set, row `content_id` must match.
- `plan_file` resolved via `confineUnderRoot` (rejects `..` and abs paths outside repo).
- `scrubGitEnv` strips `GIT_DIR`/`GIT_WORK_TREE` so child git honors `cmd.Dir` (avoids attaching worktrees to the Mayank2 checkout when the daemon runs inside a worktree).
- Push of the build branch is owned by M2-505, not this job.
