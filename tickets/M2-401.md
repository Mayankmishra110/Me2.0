## Goal
`blog.draft` and `blog.merge` jobs that take a backlog topic through Claude (task `blog`, `claude_cli`, Mayank's voice) to a full MDX post on a branch in Mayank's Mayankbuilt repo, previewed on Vercel, approved via Telegram/dashboard (D5), then merged to `main` so it goes live. This is the canonical post — M2-402/403/404 all repurpose from it.

## Acceptance criteria
- [ ] `internal/blog/draft.go` implements the `blog.draft` job: reads the next backlog topic (`config/blog-topics.md`, or a manual `/blog <topic>` from Telegram, flagged like `topics.source=manual`), calls `internal/llm.Complete(ctx, "blog", req)` to produce a full MDX post in Mayank's voice.
- [ ] Writes the MDX file into the local Mayankbuilt checkout, commits on branch `blog/<slug>`, pushes — fixed git argv (`checkout -b`, `add`, `commit`, `push`), never a shell string built from the LLM's output (CLAUDE.md non-negotiable).
- [ ] Records the resulting Vercel preview URL and creates an `approval.request` (`content_items.kind = "blog"`) with that preview link — same D5/F7 human-approval gate as every other publish path in this system.
- [ ] Reject/Redo(note) re-runs `blog.draft` with the note appended to the prompt (same redo pattern as `script.write`), max retries before dead-letter.
- [ ] On Approve: `internal/blog/merge.go` implements the `blog.merge` job — fast-forward merge of `blog/<slug>` to `main` in the Mayankbuilt repo via git (fixed argv, never force-push), so the post goes live at its canonical URL; records the live URL on a `publications` row (`platform = "mayankbuilt"`) so M2-402/403/404 can read it.
- [ ] `blog.merge` is idempotent: re-running it for an already-merged branch is a no-op success, not a duplicate merge or an error.
- [ ] The merge only ever runs after F7 approval — no direct commit to `main` before approval; force-push is never used.
- [ ] Any git credential / GitHub token used to push to Mayankbuilt comes from `internal/secrets` (DPAPI vault), never `.env` plaintext, never logged (check job errors and `events` rows for token substrings in tests).
- [ ] Table-driven tests next to each file cover: draft → approval → merge happy path (fake git repo / temp-dir remote), redo-with-note re-draft, reject path (confirm no merge happens), and idempotent re-merge.
