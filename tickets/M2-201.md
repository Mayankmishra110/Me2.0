## Notes

### Plan (2026-09-28)

M2-101 (merged into phase/p1-foundation) already added `internal/config.Channel` /
`LoadChannel` / `ValidateChannel`, which parses `config/channels/*.yaml` as part of loading
`config.yaml` and checks the generic shape (required fields, HH:MM slots, IANA tz, voice
speed > 0, duplicate id across the whole `Config.Channels` set). That package is out of this
ticket's `touches` and stays untouched.

`internal/content/channels.go` builds the **domain** layer on top of it, self-contained (loads
directly from a channels dir, no `config.yaml` needed):

1. `LoadChannels(dir string) ([]Channel, error)` — reads `*.yaml`/`*.yml` in `dir`, calls
   `config.LoadChannel` per file (reuse the existing parse + base validation, DRY), then adds
   the checks this ticket's acceptance criteria need that `internal/config` does not do:
   - `language` must be `en` or `hi` (D10/CONTEXT §1) — not just non-empty.
   - every entry in `formats` must be one of the 10 formats in CONTENT_STRATEGY §3
     (`explained_60s, myth_vs_fact, top_n, case_study, comparison, how_to, news_breakdown,
     mistakes_to_avoid, timeline, qa`) — unknown IDs rejected per acceptance criterion 1.
     Assumption: no channel file uses the Q&A format yet, so its slug `qa` is my choice, not a
     documented one — flagging as a technical assumption, not a product question.
   - `brand.caption_style` must be one of `word-highlight | karaoke | block` (DESIGN §3
     comment); `internal/config` does not check this today.
   - Converts to a `BrandKit` struct field-for-field matching `remotion/src/types.ts`
     (`primary, secondary, fontHeading, fontBody, captionStyle`), with `json` tags in that
     casing so `internal/media` can marshal it straight through later.
   - Duplicate id across the files in `dir` -> error naming both files (own check, since I'm
     not going through `config.Load`'s whole-config duplicate check).
   - Every error names the file and field (`fmt.Errorf("%s: <field>: ...", path, ...)`).

2. `Record` (a `channels` table row) + `SyncChannels(ctx, dbtx, channels, now)` — one
   `INSERT ... ON CONFLICT(id) DO UPDATE` per channel, `RETURNING *` so callers see the
   resulting row. On first insert: `status='warming'`, `warmup_started_at=now`. On conflict
   (channel already exists): only `platform/handle/language/niche` are refreshed from YAML;
   `status`/`account_ref`/`warmup_started_at` are left alone (those are runtime-owned, not
   config-owned). "First activation" = first time the row is created by sync — the YAML schema
   has no explicit active/paused/warming field (DESIGN §3), and CONTEXT/COMPLIANCE describe
   ramp-up starting "per new channel", so syncing a channel for the first time is what starts
   its ramp-up clock. Technical decision, recorded here per BOOT.md (not a product question).

3. `CapsFor(rec Record, date time.Time) Caps` — pure function of `warmup_started_at` vs
   `date`, COMPLIANCE §4 table:
   - no `warmup_started_at` (not yet synced) -> `{0,0}`.
   - week 1 -> `{ShortsPerDay:1, LongPerWeek:1}`; week 2 -> `{1,2}`; week 3 -> `{2,2}`;
     week 4+ -> `{2,4}` (COMPLIANCE gives long/week as a 3-4 *range* for week 4+; `CapsFor`
     returns the upper bound as the enforceable cap — a target within the range is a
     scheduler concern, not a cap concern). Recorded as a technical decision.
   - Does **not** special-case `status=paused` — out of scope for a pure cadence-table
     function; pause handling belongs to the scheduler ticket that calls this.

Files: `internal/content/channels.go`, `internal/content/channels_test.go`. No new migration —
`001_init.sql` already has the `channels` table with every column this ticket needs.

Table-driven tests: valid multi-channel dir loads; each invalid-config case (missing field via
`config.LoadChannel`, duplicate id, bad language, unknown format, bad caption_style) fails with
a specific error naming the file/field; `CapsFor` across weeks 1/2/3/4+/no-warmup; a DB
round-trip test (open temp sqlite, migrate, `SyncChannels` twice — first insert sets
`warmup_started_at`+`warming`, second call preserves both while refreshing `niche`).
