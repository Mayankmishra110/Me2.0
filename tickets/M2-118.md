## Goal
A real end-to-end smoke test of `mayank2 run` on `main` (e236e5d, all of P1-P6 merged) found two
production-blocking defects in `internal/httpapi`:

1. `ResolveListen` resolves every `dashboard.listen` address atomically. On a machine without the
   `tailscale` binary (the example config ships `["127.0.0.1:7070", "tailscale:7070"]`),
   `lookupTailscaleIP` fails, the whole function errors, and **nothing binds** — not even
   `127.0.0.1`. `cmd/mayank2/run.go` logs "http server stopped unexpectedly" and the
   dashboard/API is dead for the life of the process while workers keep running.
2. `GET /` serves the committed `internal/httpapi/dist/index.html` placeholder, never the real
   React dashboard from `web/dist` (M2-106's own ticket notes: "go:embed cannot escape the
   package dir" — the copy step that M2-106 expected the build/M2-110 wiring to add was never
   written).

## Acceptance criteria
- [x] `ResolveListen` resolves each configured address independently. An unresolvable `tailscale`
      sentinel (binary missing, `tailscale ip -4` fails) is skipped with a clear warning log line
      ("tailscale not available — dashboard reachable on 127.0.0.1 only"); it is an error only when
      **zero** addresses resolve/bind. Never falls back to `0.0.0.0` or any non-loopback,
      non-Tailscale address (loopback lock from M2-101/M2-106 kept intact).
- [x] `Server.ListenAndServe` binds each resolved address independently: one address failing to
      bind (port in use, etc.) does not take down an address that bound successfully.
- [x] A background retry (simple, bounded) adds the Tailscale listener later if Tailscale comes up
      after boot, when the sentinel was requested but skipped at start.
- [x] `doctor` reports Tailscale as ✅ (binary found + `tailscale ip -4` works) or ⚪ (binary not
      on PATH → feature off), never ❌ for a plain "not installed".
- [x] Table-driven tests: tailscale missing → loopback still binds; all addresses bad → error;
      never binds `0.0.0.0`.
- [x] `GET /` serves the real built SPA from `web/dist` when it has been built (`scripts/build.ps1`
      copies `web/dist` → `internal/httpapi/dist`); the previously-committed placeholder remains as
      a fallback (both embedded; runtime picks whichever `dist/` actually has an `index.html`) and
      a clear log line states which one is being served.
- [x] SPA fallback still serves `index.html` for client routes (e.g. `/approvals`); `/api/*` and
      `/media/*` are never shadowed by the SPA handler.
- [x] Go test with a fake embed FS proves SPA fallback and that `/api/health` is not shadowed.
- [x] `scripts/build.ps1` and README document the new copy step; built dashboard files are not
      committed (`internal/httpapi/dist/*` gitignored except the tracked fallback dir).

Picked up mid-task from a prior session interrupted by a rate limit; the branch already had all
the Go source/test changes done (`internal/httpapi/bind.go`, `server.go`, `spa.go`, `bind_test.go`,

session read every diff line by line (not just the ticket's own claims) to verify it end to end:

- `ResolveListen` now returns `ResolveResult{Addrs, Skipped}`, resolves/skips each address
  independently, only errors when zero resolve, and never emits a wildcard. Verified no callers
  outside `internal/httpapi` used the old `([]string, error)` signature.
- `Server.ListenAndServe` binds each resolved address independently via `startListener`, logs a
  clear warning per skipped address (the exact "tailscale not available — dashboard reachable on
  127.0.0.1 only" wording for the tailscale sentinel), only errors when zero addresses bind, and
  runs a bounded 30s-interval background retry (`retryTailscale`) that adds the Tailscale listener
  later and stops once it succeeds or ctx is cancelled.
- `doctor.go`'s `checkTailscale` returns ⚪ both for "binary not on PATH" and for "binary present
  but `tailscale ip -4` failed / no IP" — never ❌ for a plain not-installed. Confirmed by running
  `doctor` for real (no tailscale on this machine) — see manual run below.
- `spa.go` embeds both `dist` (real build target, gitignored except `.gitkeep`) and `distfallback`
  (the committed placeholder, previously at `dist/index.html`) and `distSubFS` picks whichever has
  a real `index.html`, logging which source it picked. `spaHandler` also defensively 404s
  `/api/*` and `/media/*` so it can never shadow those routes even if reached directly.
- Found and fixed one real gap the prior session left incomplete: the acceptance criteria and the
  ticket's own `touches` list both call for README documentation of the new copy step, but
  `README.md` had no diff at all. Added a paragraph to the "Build and start at logon" section
  explaining that `scripts/build.ps1` copies `web\dist` → `internal\httpapi\dist` (`go:embed`
  cannot reach outside its own package directory), that the copy is gitignored, and that the
  committed `internal/httpapi/distfallback` placeholder is served until `web\` has been built at
  least once.
- Confirmed `internal/httpapi/dist/*` is gitignored (only `.gitkeep` tracked) via
  `git check-ignore -v` after a real `scripts/build.ps1` run populated it with a full Vite build.

### Manual proof (real run, throwaway config outside the repo)

being fixed): it built `web\dist`, copied it into `internal\httpapi\dist`, and built
`bin\mayank2.exe`. Confirmed `internal/httpapi/dist/*` stayed gitignored the whole time
