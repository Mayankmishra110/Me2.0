## Goal
A real end-to-end smoke test of `mayank2 run` on `main` (e236e5d, all of P1-P6 merged) found two
production-blocking defects in `internal/httpapi`:

1. `ResolveListen` resolves every `dashboard.listen` address atomically. On a machine without the
   `tailscale` binary (the example config ships `["127.0.0.1:7070", "tailscale:7070"]`),
   `lookupTailscaleIP` fails, the whole function errors, and **nothing binds** — not even
   `127.0.0.1`. `cmd/mayank2/run.go` logs "http server stopped unexpectedly" and the
   dashboard/API is dead for the life of the process while workers keep running.
2. `GET /` serves the committed `internal/httpapi/dist/index.html` placeholder, never the real
   React dashboard from `web/dist` (M2-106's own ticket notes: "go:embed cannot escape the
   package dir" — the copy step that M2-106 expected the build/M2-110 wiring to add was never
   written).

## Acceptance criteria
- [x] `ResolveListen` resolves each configured address independently. An unresolvable `tailscale`
      sentinel (binary missing, `tailscale ip -4` fails) is skipped with a clear warning log line
      ("tailscale not available — dashboard reachable on 127.0.0.1 only"); it is an error only when
      **zero** addresses resolve/bind. Never falls back to `0.0.0.0` or any non-loopback,
      non-Tailscale address (loopback lock from M2-101/M2-106 kept intact).
- [x] `Server.ListenAndServe` binds each resolved address independently: one address failing to
      bind (port in use, etc.) does not take down an address that bound successfully.
- [x] A background retry (simple, bounded) adds the Tailscale listener later if Tailscale comes up
      after boot, when the sentinel was requested but skipped at start.
- [x] `doctor` reports Tailscale as ✅ (binary found + `tailscale ip -4` works) or ⚪ (binary not
      on PATH → feature off), never ❌ for a plain "not installed".
- [x] Table-driven tests: tailscale missing → loopback still binds; all addresses bad → error;
      never binds `0.0.0.0`.
- [x] `GET /` serves the real built SPA from `web/dist` when it has been built (`scripts/build.ps1`
      copies `web/dist` → `internal/httpapi/dist`); the previously-committed placeholder remains as
      a fallback (both embedded; runtime picks whichever `dist/` actually has an `index.html`) and
      a clear log line states which one is being served.
- [x] SPA fallback still serves `index.html` for client routes (e.g. `/approvals`); `/api/*` and
      `/media/*` are never shadowed by the SPA handler.
- [x] Go test with a fake embed FS proves SPA fallback and that `/api/health` is not shadowed.
- [x] `scripts/build.ps1` and README document the new copy step; built dashboard files are not
      committed (`internal/httpapi/dist/*` gitignored except the tracked fallback dir).

## Review

Independent qa/sec re-review (not the build session above), 2026-09-29, in worktree
`data/worktrees/m2-118`, branch `m2/M2-118` at `2f07f80`. Did not trust the build report at face
value — re-derived every claim from the real source and real command output.

1. **Bind resilience (`internal/httpapi/bind.go`, `server.go`)**: read `ResolveListen`/`resolveOne`
   and `ListenAndServe`/`startListener` end to end. Each configured address is genuinely resolved
   independently in a `for` loop over `addrs` (`resolveOne` per entry, appended to `Skipped` or
   `Addrs`, never a shared try/catch that fails atomically), and each resolved address is bound
   independently in `startListener` (one `net.Listen` call per address, failures logged and
   skipped via `return false`, never aborting the loop in `ListenAndServe`). `ResolveListen`
   errors only when `len(result.Addrs) == 0` (bind.go:101-103); `ListenAndServe` errors only when
   `bound == 0` (server.go:154-157). Confirmed with table-driven tests
   (`TestResolveListen_tailscaleMissingStillBindsLoopback`,
   `TestResolveListen_allAddressesBadIsError`,
   `TestListenAndServe_tailscaleMissingStillServesLoopback`,
   `TestListenAndServe_allAddressesBadErrors`) and a real manual run (below).

2. **Security property — loopback lock — HELD.** Grepped `internal/httpapi/` and `cmd/mayank2/`
   for `0.0.0.0`, `::`, `[::]`, and bare `net.Listen("tcp", ":...")`: the only matches are (a) the
   explicit rejection in `splitHostPort` (bind.go:155-157, refuses `0.0.0.0`/`::`/`[::]` as a
   configured host), (b) comments describing what's rejected, and (c) test cases proving rejection
   (`TestResolveListen_rejectsWildcardAndLAN`, `TestResolveListen_neverBindsWildcard` — a
   table-driven sweep with tailscale both up and down). `resolveOne` (bind.go:109-129) only ever
   returns `127.0.0.1`, the resolved Tailscale IP, or a literal that already equals the resolved
   Tailscale IP — no code path constructs or falls back to a wildcard or LAN/public address. This
   session's fix changes *which configured addresses may fail gracefully* (each is independent,
   only zero-bound is fatal), never *what addresses are allowed to bind* — the allow-list in
   `resolveOne`/`splitHostPort` is unchanged from the loopback-lock design. Confirmed additionally
   by a real process run on this machine (no tailscale binary) serving only on `127.0.0.1:7091`
   (see manual proof below) and by grepping the built `internal/httpapi/dist/assets/*.js` false
   positive away (Vite's bundled Node `http` library source, not app code).

3. **`retryTailscale` (server.go:224-248)**: a `time.Ticker` on a 30s interval inside a `for/select`
   that returns immediately on `<-ctx.Done()` — bounded, no leak, respects cancellation. On success
   it calls `s.startListener`, which checks `s.boundAddrs[addr]` under `s.mu` first (server.go:180-185)
   and returns `false` without creating a second listener if a static entry already covered that
   address — no duplicate-listener path. `shutdown()` iterates `s.servers` (which `startListener`
   appends to under the same mutex regardless of whether it was called from the initial loop or
   from the retry goroutine), so a late Tailscale listener is shut down correctly too. Noted one
   cosmetic (non-blocking) detail: `errCh`'s buffer (`len(listen)+4`) has "headroom for later retry
   additions" by design (server.go:147 comment) precisely so a late add's eventual close/error
   write never blocks; `drain()`'s count doesn't track late additions, but since the channel is
   sufficiently buffered this cannot deadlock or leak a goroutine — not a real bug, not blocking.

4. **Dashboard embedding (`internal/httpapi/spa.go`)**: `distSubFS` prefers `dist/` (real build)
   over `distfallback/` (placeholder) via `hasIndex` on the real dist sub-FS first, falling back
   only if that check fails (spa.go:30-41) — confirmed with
   `TestDistSubFS_fallsBackWhenNoRealBuild`. Routing precedence checked directly in
   `internal/httpapi/routes.go`: `/api/` and `/media/` are registered on the mux ahead of `/`
   (spaHandler) — `mux.Handle("/api/", ...)` / `mux.Handle("/media/", ...)` at routes.go:49-50,
   `mux.Handle("/", spaHandler(s.web))` at routes.go:53 — so Go's `http.ServeMux` longest-prefix
   match always resolves API/media routes first; `spaHandler` itself also defensively 404s
   `/api/*` and `/media/*` (spa.go:61-64) if ever reached directly. Confirmed end to end with
   `TestRoutes_healthNotShadowedByBuiltDashboard` and `TestSPA_neverShadowsAPIOrMedia`, and for
   real with `curl /api/health` (200, JSON) and `curl /approvals` (200, dashboard HTML shell) below.
   `.gitignore` genuinely excludes `internal/httpapi/dist/*` except `.gitkeep`
   (`.gitignore:12-13`): verified by running `scripts/build.ps1`-equivalent steps for real (`cd web
   && npm ci && npm run build`, copy `web/dist` → `internal/httpapi/dist`) and then
   `git check-ignore -v` on the freshly-copied `index.html` and both hashed asset files — all three
   reported as ignored by `.gitignore:12`, and `git status --short internal/httpapi/dist/` showed
   nothing (no accidental staging risk).
