## Goal
Take the approved, now-live Mayankbuilt post and produce a LinkedIn-native repost — shorter, its own hook, not a raw copy-paste — then publish it via LinkedIn's official Posts API once Mayank approves it (D5).

## Acceptance criteria
- [ ] `internal/blog/repurpose_linkedin.go` implements the LinkedIn leg of `blog.repurpose`: input is the live Mayankbuilt post (URL + body, from M2-401's `publications` row); calls `internal/llm.Complete(ctx, "blog", req)` (still the `blog` task/Claude route — this is rewriting the same post, not a content-engine task) to produce a LinkedIn-native draft: shorter, its own hook, and a link back to the canonical post.
- [ ] Output is not a raw copy-paste of the blog post — a test asserts the LinkedIn draft text is substantially different from (shorter than, different opening line than) the source MDX body.
- [ ] Creates an `approval.request` (`content_items.kind = "blog"`, platform `"linkedin"`) with the draft text and source link; Reject/Redo(note) re-runs the repurpose step with the note, same pattern as M2-401.
- [ ] `internal/publish/linkedin.go` implements `Publisher`: `Platform()` returns `"linkedin"`; `Publish(ctx, PublishRequest)` is idempotent on `p.IdempotencyKey` (checks `publications.idempotency_key` before calling the API).
- [ ] Refuses to call the API unless the item's `approvals` row is `status = approved` (D5, F7) — same `RequireApproved` helper pattern as M2-301/302/303/304.
- [ ] Publishes via LinkedIn's official Posts API under Mayank's personal LinkedIn member URN, using an access token read from `internal/secrets` (DPAPI vault) by account ref — never `.env` plaintext, never logged.
- [ ] Respects the LinkedIn daily cap (≤ 1 post/day, COMPLIANCE §4) — fails closed rather than queuing past it.
- [ ] On success, records `external_id` and post `url` in `publications`; on failure, wraps the API error with `%w`, error detail (not the token) in `last_error`.
- [ ] Table-driven tests cover: repurposed text differs from source, idempotent replay, missing approval, cap exceeded, happy-path publish against a fake LinkedIn API server (`httptest`).

## Notes
- Not fully certain of LinkedIn's current Posts API shape — whether it's still the legacy `ugcPosts` endpoint or the newer `posts` endpoint, required scopes (`w_member_social` vs newer scope names), and current API-access tier/app-review requirements (LinkedIn has tightened developer-app approval before). **Double-check against live LinkedIn API docs before implementing.**
- CONTENT_STRATEGY §4's craft rules are written for video scripts (hook in first 2 seconds, loopable last line, chapters, etc.), not LinkedIn text posts. This ticket adapts the underlying principle — a real, specific hook rather than a teaser dump of the article — to a text post; there is no LinkedIn-specific craft section anywhere in the docs, so the repurpose prompt's exact style rules are this ticket's own interpretation and should be checked against real LinkedIn post examples during implementation, not treated as spec.
- Docs don't say whether there's more than one LinkedIn account in scope; assumed a single Mayank-personal LinkedIn account per CONTEXT D12 — flag if that's wrong.
