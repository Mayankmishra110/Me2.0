## Goal
Append-only `events` with an in-process fan-out that the HTTP layer streams as SSE.

## Acceptance criteria
- [ ] `events.Emit(ctx, actor, kind, ref, message, data)` writes the row and publishes to subscribers.
- [ ] Subscribers are non-blocking (a slow consumer drops messages, never blocks emitters).
- [ ] Event kinds from the SPEC §4 SSE list.
- [ ] Tests for fan-out and slow-consumer behavior.

## Docs
ARCHITECTURE §2 · SPEC §4

## Notes

### Plan (be-2, 2026-09-28)

- Schema (from migrations/001_init.sql): `events(id TEXT PK, at TEXT, actor TEXT CHECK IN(agent,user,system), kind TEXT, ref TEXT NULL, message TEXT DEFAULT '', data TEXT NULL json)`, index `events_at`. `internal/db.Open` gives a `*sql.DB` (WAL, busy_timeout=5000); events uses it directly, no repository interface (matches existing `internal/db` style).
- Files (all in `internal/events/`): `events.go` (Event, Actor, Kind consts, Bus, `Emit`, `Recent`), `hub.go` (`Hub`, `Subscribe`/`Publish`, bounded+drop-oldest), `id.go` (dependency-free ULID-style sortable id: 48-bit ms timestamp + 80-bit random, Crockford base32, monotonic within the same ms), `doc.go` (package doc with the SSE-handler usage pattern for M2-106), plus `_test.go` files for each.
- API: `Bus.Emit(ctx, actor Actor, kind, ref, message string, data any) (Event, error)` — matches this ticket's acceptance criterion exactly (not the `Log(ctx, kind, payload)` shorthand sketched in the crew brief); it writes the row then fans out. `Bus.Subscribe(ctx) (<-chan Event, func())` for consumers (M2-106's SSE handler). Kept `kind` as a free string (not restricted to the SPEC §4 SSE list) since ARCHITECTURE §4 documents `events` as the general append-only audit table for every subsystem, not only the 5 kinds the `/api/events/stream` endpoint contract names — those 5 are exported as `Kind*` constants so producers use exact spec strings.
- Concurrency: `Hub` holds a mutex; `Publish` iterates subscriber channels under the lock doing non-blocking sends (`select`/`default`), dropping the oldest queued event and retrying once if a channel is full, so a slow/gone subscriber never blocks the writer or other subscribers. `Subscribe` returns an unsubscribe func; a watcher goroutine exits on either `ctx.Done()` or the unsubscribe func itself (no leak either way), and the channel is closed under the same lock that removes it from the subscriber map (safe against a concurrent `Publish`).
- No new dependency: `google/uuid`/`oklog/ulid` are not in the module cache here (no network fetch attempted, would touch the shared `go.mod` other in-flight tickets also depend on) — wrote a small internal ULID-style encoder instead.
- Tests (table-driven where it fits): multiple subscribers all receive one `Emit`; a subscriber that never reads doesn't block `Emit`/other subscribers (bounded wait, no real sleeps beyond a few ms); persisted rows are readable back via `Recent` in chronological order; `Emit` validation errors (bad actor, empty kind); unsubscribe (both explicit and via ctx cancel) stops delivery and the channel closes, checked with a bounded `runtime.NumGoroutine()` poll for no leak. `go test -race`: this machine has `CGO_ENABLED=0` and no `gcc` on PATH, so `-race` cannot run here — noted, not run.
