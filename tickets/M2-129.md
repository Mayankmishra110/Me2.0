## Goal
`web/src/main.tsx` started the MSW mock worker on every build unless the build-time env var
`VITE_USE_MSW=false` was set — and nothing in `scripts/build.ps1` or any env file ever set it. Once
M2-106 embedded `web/dist` into `bin/mayank2.exe`, every real browser session against the production
binary got its `fetch()` calls intercepted by MSW and answered with fake mock data *before* the real
server was ever reached. `RequireAuth` (M2-125) depends on a real `GET /api/agents` 401 to redirect to
`/login`; MSW silently returned a fake 200 for it instead, so the real login screen M2-125 built never
actually showed to a real user — even though server-side auth (`internal/httpapi`) was completely
correct. This exact risk was flagged and left unfixed in `docs/audit/p1-foundation/M2-107.md` ("Known
gaps and follow-ups" #1), which recommended gating on `import.meta.env.DEV` instead of an opt-in flag
that has to be remembered at build time.

## Acceptance criteria
- [x] `web/src/main.tsx` starts MSW only when `import.meta.env.DEV` is true (Vite's own dev-mode flag:
  true for `vite`/`npm run dev`, false for `vite build`'s production output). No build-time env var to
  remember.
- [x] `npm run build`'s output bundle contains zero MSW code — confirmed by grepping the built
  `dist/assets/*.js` for `msw`/`setupWorker`/`mockServiceWorker` (0 matches); Vite dead-code-eliminates
  the whole `await import('./mocks/browser')` branch once the guard is a statically-false `import.meta.env.DEV`.
- [x] `web/public/mockServiceWorker.js` is no longer copied into `web/dist` (and therefore not embedded
  into `bin/mayank2.exe` via `internal/httpapi`'s `go:embed`): a small `vite.config.ts` plugin
  (`dropMswAsset`, build-only, `closeBundle` hook) removes `dist/mockServiceWorker.js` after Vite's
  `publicDir` copy. The dead inert-file risk called out as acceptable-if-left is removed instead, since
  it was easy.
- [x] `npm run dev` is unaffected: MSW still starts (`import.meta.env.DEV` is true under `vite`), and the
  dashboard still shows mock data from `web/src/mocks/data.ts` in a real browser.
- [x] The Vitest suite is unaffected: `web/src/test/setup.ts` wires MSW via `msw/node`'s
  `server.listen()`, independent of `main.tsx`'s browser-startup code, which already early-returns for
  `import.meta.env.MODE === 'test'`.
- [x] Real-browser regression check on the actual built binary: a fresh Playwright Chromium context
  (real `fetch()`, no `APIRequestContext`) with no cookies, against `bin/mayank2.exe` run with a
  throwaway config/env, lands on `/login` and renders the token form — not the dashboard. Logging in
  with the real `DASHBOARD_TOKEN` then shows the real (empty/zero) dashboard, not MSW's mock agent
  roster.

## Notes

### Root cause
`web/src/main.tsx`'s `prepare()` only skipped starting MSW for `import.meta.env.MODE === 'test'` or an
explicit `VITE_USE_MSW === 'false'`. `scripts/build.ps1` runs plain `npm run build` with no env var set,
so `vite build`'s production output always shipped with MSW live. `vite-env.d.ts` declared the
`VITE_USE_MSW` ambient type; it's removed along with the dead code path.

### Fix
- `web/src/main.tsx`: replaced the `VITE_USE_MSW === 'false'` opt-out check with `if (!import.meta.env.DEV) return`.
  `DEV`/`PROD` are Vite's own built-in, statically-replaced env flags — true for `vite`/`vite dev`, false
  for `vite build` — so there is no flag to forget at build time, which is exactly how this slipped
  through in the first place.
- `web/src/vite-env.d.ts`: dropped the now-unused `VITE_USE_MSW` ambient type declaration.
- `web/vite.config.ts`: added a small `dropMswAsset()` plugin (`apply: 'build'`, `closeBundle` hook) that
  removes `dist/mockServiceWorker.js` after the build, so the inert file doesn't even ship in `dist` /
  the embedded binary. Kept deliberately minimal — one `rm` call, no new dependency.

### Real-browser regression check (the one that matters — this bug doesn't reproduce via curl/API clients)
Built the real binary (`scripts/build.ps1`), ran `bin\mayank2.exe run -config <throwaway config.yaml>
-env <throwaway .env with DASHBOARD_TOKEN>` outside the repo (`dashboard.listen: ["127.0.0.1:7071"]`,
no Tailscale needed per `internal/httpapi/bind.go`'s graceful skip). Confirmed:
- `curl http://127.0.0.1:7071/api/agents` with no cookie → real `401 Unauthorized` from the server
  (server-side auth was never the problem).
- Playwright Chromium, fresh context (no cookies), `goto http://127.0.0.1:7071/` →
  **lands on `/login`**, body text `"Mayank 2.0 Enter your dashboard token to continue. Token Sign in"`,
  a real password/token input present, **zero requests for `mockServiceWorker.js`**. This is the exact
  regression check that failed before this fix (MSW would have intercepted the `/api/agents` 401 and
  `RequireAuth` would never have redirected here).
- Filling the real `DASHBOARD_TOKEN` and submitting → lands back on `/`, real dashboard renders with
  live zero-state data (`"0 pending"`, `"0 / 8"`, `"No alerts."`) — not MSW's mock DB (which seeds a
  12-agent roster including `Scout`/`Research`/`Voice`/etc. with fake timestamps and a dead
  `analytics.pull` job).

### Dev-mode regression check (unaffected)
`npm run dev` (Vite dev server) in a real Playwright Chromium browser: page renders MSW's mock data —
`"Scout"`, `"Dead job analytics.pull: YouTube Analytics quota exhausted"` (from `web/src/mocks/data.ts`)
— confirming MSW is still fully active under `vite dev`/`import.meta.env.DEV === true`, unchanged from
before this fix.
