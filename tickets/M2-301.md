## Goal
A `Publisher` for Instagram Reels using the Meta Graph API's container/publish flow, so an approved render reaches the Instagram Professional account linked to the Facebook Page.

## Acceptance criteria
- [ ] `internal/publish/instagram.go` implements `Publisher`: `Platform() string` returns `"instagram"`; `Publish(ctx, PublishRequest) (PublishResult, error)` is idempotent on `p.IdempotencyKey` (checks `publications.idempotency_key` before calling the Graph API; a repeat call with the same key returns the stored result without a second API call).
- [ ] Refuses to call the Graph API unless the item's `approvals` row is `status = approved` (D5, F7) — check via the same `RequireApproved` helper F2-era publishers use; missing/non-approved approval is a permanent error, not a retry.
- [ ] Gets a temporary public URL for the render from `internal/storage` (R2 presigned GET, M2-213) — Instagram's container-creation call takes a public `video_url`/`image_url`, never a file upload.
- [ ] Two-step publish against the Graph API: (1) `POST /{ig-user-id}/media` with the presigned URL and caption to create a media container, (2) poll container status until `FINISHED`, (3) `POST /{ig-user-id}/media_publish` with the container ID. Polling has a bounded timeout and backoff; `IN_PROGRESS`/`ERROR` statuses are handled explicitly; a stuck container fails the job (retryable) rather than hanging the worker.
- [ ] Caption includes the affiliate/paid-partnership disclosure text when `content_items` marks it, and the AI-disclosure label when the compliance report's `disclosures.synthetic` is true (COMPLIANCE §1 Meta row).
- [ ] Long-lived Page/IG access token is read from `internal/secrets` (DPAPI vault, M2-110) by account ref — never read from `.env` directly, never logged (check job error messages and `events` rows for token substrings in tests).
- [ ] On success, records `external_id` (Graph media ID) and permalink `url` in `publications`; on failure, wraps the Graph API error with `%w` and includes the Graph API's `error.code`/`error.message` (not the raw token) in `last_error`.
- [ ] Respects the Instagram Reels daily cap (≤ 3/day per account, COMPLIANCE §4) — job refuses to publish past the cap rather than queuing an over-cap post; caller (scheduler/approval flow) is expected to have already checked this, but the publisher fails closed if asked to publish beyond it.
- [ ] Table-driven tests next to the file cover: idempotent replay, missing approval, container stuck in `IN_PROGRESS` past timeout, container `ERROR` status, and a happy-path publish against a fake Graph API server (`httptest`).

## Notes
- Not fully certain of current Meta container-status polling field names/values (`status_code` vs `status`, exact enum spelling, recommended poll interval) or the current publishing-rate limit headers — **double-check against the live Meta Graph API docs for Instagram Content Publishing before implementing**, the spec above is based on the general container/publish shape, which may have shifted.
- Also verify the current API version path (`/v2x.x/`) and whether a Business Login vs. legacy Facebook Login token is required for the IG user ID lookup — Meta has changed this more than once.
- Instagram requires a Professional account linked to a Facebook Page (CONTEXT §6); the `account_ref` passed to `internal/secrets` should resolve to the IG Business Account ID, not the Page ID — confirm the lookup chain (Page → IG Business Account) works before assuming a single stored ID is enough.
