## Goal
A `Publisher` for Instagram Reels using the Meta Graph API's container/publish flow, so an approved render reaches the Instagram Professional account linked to the Facebook Page.

## Acceptance criteria
- [x] `internal/publish/instagram.go` implements `Publisher`: `Platform() string` returns `"instagram"`; `Publish(ctx, PublishRequest) (PublishResult, error)` is idempotent on `p.IdempotencyKey` (checks `publications.idempotency_key` before calling the Graph API; a repeat call with the same key returns the stored result without a second API call).
      Proven: `TestInstagram_Idempotent`, `lookupPublished`.
- [x] Refuses to call the Graph API unless the item's `approvals` row is `status = approved` (D5, F7) — check via `content.RequireApproved`; missing/non-approved approval is a permanent error (`queue.Permanent` in `Handle`).
      Proven: `TestInstagram_MissingApproval`.
- [x] Gets a temporary public URL for the render from `internal/storage` (R2 `PresignGET`) — Graph gets `video_url`, never a local file upload.
      Proven: `igPresigner` + happy-path / HTTP tests.
- [x] Two-step publish: `POST /{ig-user-id}/media` (`media_type=REELS`) → poll `status_code` until `FINISHED` → `POST /{ig-user-id}/media_publish` with `creation_id`. Bounded poll timeout (wall clock); `IN_PROGRESS` stuck → retryable error; `ERROR`/`EXPIRED` handled.
      Proven: `TestInstagram_ContainerStuck`, `TestInstagram_ContainerError`, `TestInstagram_HTTPHappyPath`. Field name/values are a best guess from the general container/publish shape, **not verified against live docs** — see Notes.
- [x] Caption includes `#ad Paid partnership` when `PaidPromotion` and AI-disclosure when `ContainsSynthetic`.
      Proven: `igCaption` assert in `TestInstagram_PublishHappyPath`.
- [x] Long-lived token via `TokenSourceFor` (secrets vault adapter) — never `.env`, never logged; Graph error bodies and returned errors redact `access_token=`.
      Proven: `TestInstagram_TokenNeverLogged`, `TestInstagram_TokenNotInLastError`.
- [x] On success records `external_id` + permalink `url` in `publications`; failures include Graph `error.code`/`message` (not token) in `publications.error`.
- [x] Daily cap ≤ 3/day per account via `quotas` (`instagram:<account>`); fails closed.
      Proven: `TestInstagram_DailyCap`.
- [x] Tests: idempotent replay, missing approval, stuck `IN_PROGRESS`, `ERROR` status, httptest happy path, daily cap, token redaction.

## Notes

### Technical decisions
- Graph host `graph.facebook.com/v21.0` (matches `internal/secrets/platform.go`'s existing `meta` OAuth endpoint version, so at least internally consistent — not independently re-verified as Meta's current version for Content Publishing specifically). `account` passed to `TokenSourceFor`/`CreateReelContainer` is the IG Business Account ID (not the Page ID) — the Publisher assumes the caller already resolved Page → IG Business Account; that lookup chain itself is not implemented here (out of `touches`).
- Poll: `igDefaultPollInterval = 15s`, `igDefaultPollTimeout = 5m`, both injectable (`Instagram.PollInterval`/`PollTimeout`) and overridden to milliseconds in tests. These are a reasonable-guess default, not a value taken from a rate-limit header or live docs.
- Poll deadline is computed from `time.Now()` (wall clock), not the injectable `Now` field, specifically so a frozen/mocked clock in tests can't hang a worker forever — `Now` is only used for DB timestamps and the quota window.
- Token never logged: `igRedact` strips `access_token=`, `bearer `, `oauth ` substrings (case-insensitive) from every Graph HTTP response body and every returned error before it's stored in `publications.error` or passed to `slog`. Verified by two tests, not just asserted: `TestIgRedact` (unit, several shapes) and `TestInstagram_TokenNeverLogged`/`TestInstagram_TokenNotInLastError` (end-to-end: fake token flows into a Graph error, the stored `publications.error` and returned `err.Error()` are asserted to not contain the literal token string).
- Daemon wiring (`TokenSourceFor` ← `internal/secrets`, enqueue `publish.instagram` from `publications` rows, Page→IG Business Account ID resolution) is **not built** — same gap M2-211's independent audit flagged for YouTube. `Instagram` is unit-tested end to end against fakes/`httptest`, never against the real daemon or real Meta API.
- `needs-sec: yes` — OAuth tokens read via `TokenSourceFor`, network calls, publish path.

### ⚠️ Flagged for live-docs verification before this ever runs for real
Per the ticket's own original Notes, I have no live Meta API access in this environment either, so the
following are still **best guesses from the general container/publish shape**, not confirmed:
1. **Container status field name/values.** Code reads `status_code` from `GET /{container-id}?fields=status_code`
   and treats `FINISHED`/`PUBLISHED` as success, `ERROR`/`EXPIRED` as failure, anything else (esp. `IN_PROGRESS`)
   as still-polling. Meta has used both `status` and `status_code` in different API eras/docs — confirm the
   current field name and the complete enum before go-live.
2. **API version path.** Hardcoded to `v21.0` (`igGraphVersion` const, and matches the existing `meta` OAuth
   endpoint in `internal/secrets/platform.go`) — confirm this is still current and not deprecated by the time
   this ships; Meta bumps versions roughly twice a year and retires old ones on a schedule.
3. **Business Login vs. legacy Facebook Login token requirements** for the IG user ID / Business Account lookup
   — not verified; the code just takes whatever `account` string it's given as the IG Business Account ID and
   calls the Graph endpoints with it.
4. **Page → IG Business Account resolution.** The ticket's own Notes flagged this — confirm the `account_ref`
   stored for a `meta`/`instagram` channel actually resolves to the IG Business Account ID (not the Page ID)
   before this publisher is wired into the daemon; this file assumes that resolution already happened upstream.
5. **Poll interval/timeout and any rate-limit headers.** `15s`/`5m` are not sourced from a current rate-limit
   or recommended-poll-interval doc — just a reasonable-sounding default with backoff-by-fixed-interval
   (no exponential backoff was added; flag if Meta's guidance wants one).
6. **Rate-limit / quota headers.** Not read or enforced beyond our own DB-side daily cap (`quotas` table,
   ≤3/day) — Meta's own publishing rate limits (e.g. content publishing limit per 24h at the platform level,
   separate from our product-level cap) are not checked.
