## Goal
A `Publisher` for the X business account: uploads the short-form render as media and posts it via X API v2.

## Acceptance criteria
- [ ] `internal/publish/x.go` implements `Publisher`: `Platform() string` returns `"x"`; `Publish(ctx, PublishRequest) (PublishResult, error)` is idempotent on `p.IdempotencyKey`.
- [ ] Refuses to call the API unless the item's `approvals` row is `status = approved` (D5, F7).
- [ ] Uploads video via the X media upload endpoint (chunked INIT/APPEND/FINALIZE for video, per X's media upload flow) reading the render directly from local disk (`data/media/renders/...`) — X's upload API accepts direct binary upload, so this publisher does **not** need the R2 presigned-URL step that Instagram/Facebook require; confirm this in Notes since it's a real difference between platforms in the same ticket batch.
- [ ] Polls media processing status (`STATUS` check on the upload) until the video is ready before referencing its `media_id` in the tweet; a stuck/failed processing status fails the job (retryable) rather than hanging.
- [ ] Posts the tweet via `POST /2/tweets` with the uploaded `media_id`, caption/text from `content_items` (respecting X's character limit — truncate or reject over-length text per format rules, don't silently cut mid-word).
- [ ] Uses OAuth (1.0a user context for media upload, or OAuth 2.0 user context/app-only as required by the current X API v2 media + tweet endpoints — see Notes) with credentials loaded from `internal/secrets` (DPAPI vault) for the **business** account specifically — never the personal X account's credentials (COMPLIANCE §1: business and personal X **never** share posts or credentials, CONTEXT D12).
- [ ] On success, records `external_id` (tweet ID) and tweet `url` in `publications`; on failure, wraps errors with `%w`, includes the X API error detail (not the token) in `last_error`.
- [ ] Respects the X business daily cap (≤ 5 posts/day, COMPLIANCE §4); fails closed rather than posting past it.
- [ ] Table-driven tests next to the file cover: idempotent replay, missing approval, media processing stuck/`failed` status, over-length caption handling, and a happy-path publish against a fake X API server (`httptest`).

## Notes
- Not fully certain of the current X API v2 media upload auth requirement (whether chunked video upload still requires OAuth 1.0a specifically, or whether OAuth 2.0 user-context now covers it end to end) and the current free/basic tier's exact posting and media-upload rate limits — X's API tiers and pricing have changed repeatedly. **Double-check against current official X API v2 docs before implementing**, and confirm which paid tier (if any) this business account needs for video posting, since the free tier has historically been read-restricted or very low volume.
- Confirm the current chunked upload endpoint path and whether it's still under `/1.1/media/upload.json` (v1.1 media endpoints persisting alongside v2 tweet endpoints is a known quirk of X's API — don't assume everything is under `/2/`).
- Hard rule to re-verify in code review: nothing in this publisher may ever read or reference the personal X account's stored token — keep the two account refs structurally separate (e.g. distinct `account_ref` strings resolved through `internal/secrets`, no shared default).
